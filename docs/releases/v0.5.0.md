AmuOSのv0.5.0プレリリースです。この版では、これまでに実装した認証・権限・監視・バックアップと復元を、まとめて検証することに取り組みました。Linux・WindowsのCIに負荷や障害からの回復の確認を加え、その中で見つかった、容量不足のあとに復元をやり直せなくなる不具合を修正しています。まだ開発途中ですが、試していただいて気づいたことがあれば、Issueで教えていただけるととても助かります。

> [!WARNING]
> 開発途中のソフトウェアです。今回の確認はCIを中心としたもので、すべての環境や長期間の運用を保証するものではありません。APIやデータ形式も予告なく変わることがあります。本番環境やインターネットに公開された環境での利用はお控えください。

## 今回の変更

- **容量不足後の復元を修正**：作業用ファイルを書き込む途中でディスクがいっぱいになると、不完全なファイルが残り、空き容量を戻しても次の復元が拒否される場合がありました。書き込みに失敗したファイルを片付け、復元をやり直せるようにしました。容量不足の確認では、既存のデータベースが変更されないことも確かめています。
- **権限の確認を追加**：ホストごとに異なるロールを持つ利用者について、範囲外の操作や全体管理ができないこと、権限の剥奪がログイン中のセッションにも反映されること、無効化してから再び有効にしても古いセッションが復活しないことを確認しました。
- **反復操作と復元の確認を追加**：10ホスト・同時5ユーザーで監視値の送信と収集タスクを処理し、重複送信でも記録が増えないことを確認しました。別の空の状態ディレクトリへの復元では、履歴・タスク・権限の一致、古い資格情報の拒否、Agentの再登録後の収集再開も確認しています。
- **監視データの保持と再接続を確認**：10ホスト・15秒間隔・7日分に相当する403,200件のデータで、集約と期限後の削除を確認しました。画面のテストにも、Agentの停止による切断表示、Control PlaneとAgentの再起動後の接続復帰、失効・削除の確認を加えました。
- **Goの最低版を1.27.3に統一**：証明書の検証に関する標準ライブラリの修正を含む版を使用します。ソースからビルドする場合も、Go 1.27.3以降が必要です。
- **案内と画面例を更新**：READMEに英語版を加え、現在の機能・制約・導入先・今後の計画を整理しました。画面例もサンプルデータで撮り直しています。詳細資料とWeb画面は、引き続き主に日本語です。

## はじめかた

Windowsでは `amuos_0.5.0_windows_amd64.zip`、Linuxでは `amuos_0.5.0_linux_amd64.tar.gz` と `SHA256SUMS` をダウンロードし、ハッシュを照合してから展開してください。

Windowsは同梱の `INSTALL-WINDOWS.md`、Linuxは `INSTALL.md` に、Control Planeの導入、初回設定、Agentの登録、更新と切り戻しの手順があります。Windowsサービスの登録には、管理者として起動した64ビットPowerShellが必要です。

## v0.4.0 からの更新

データベースの形式はスキーマv13のままで、この版で新しい移行はありません。Linux・Windowsとも、同梱の導入手順の「更新」に従い、停止・更新前バックアップ・本体の差し替え・再起動を行ってください。Control PlaneとAgentの両方を、この版へ更新してください。

バックアップからの復元は、従来どおり作成時と同じ版の本体で行います。v0.4.0で作ったバックアップをv0.5.0へ直接復元する方法には対応していません。切り戻しに備え、旧本体と更新前のバックアップを組で保管してください。

Control Planeをバックアップから復元した場合は、ログイン中のセッションとAgentの資格情報が無効になります。各Agentを新しいコードで登録し直してください。切り戻しで復元する場合も同じです。

## まだできないこと

- ファイル管理、アプリのデプロイと実行環境の設定、Docker/Compose、VM管理。これらは今後の版で取り組む予定です
- 管理画面からのWindowsサービスやsystemdサービスの開始・停止。systemdの状態取得はLinuxのみです
- WindowsでのLoad・Swap・起動時刻、64論理CPUを超えるホストのCPU使用率の取得。ディスクI/Oも監視カウンターが利用できる環境に限られます
- 自動バックアップのスケジュール、Webからの復元、異なる版へのバックアップの直接復元

## 確認した環境

- GitHub ActionsのLinux・Windowsで、Goのテストと静的検査、認可・反復操作・監視データの保持・復元、依存関係の脆弱性検査を実行しました。Linuxでは専用の小さいファイルシステムを容量不足にし、既存データを保ったまま再復元できることを確認しました。
- Ubuntu 24.04・Debian 13での配布物の導入、Ubuntuのsystemdによる常駐・更新・切り戻し、Ubuntuで作ったバックアップの空のDebian環境への復元を確認しました。Windowsでも、配布物によるサービス導入・更新・切り戻しと、実Agentを使ったブラウザーE2Eを確認しました。
- Linuxのrace検査では、並行送信やタスク配送、既存の保持・集約境界などを確認しました。403,200件の全量試験は計測負荷が大きいためrace実行から分け、両OSの通常試験で必須にしています。
- 7日分のデータは時刻を指定して生成したもので、実時間で7日間運転した結果ではありません。403,200件の全量での暗号化バックアップ性能、実機での長時間運用、電源断を伴う確認は実施していません。試験条件と範囲は `docs/FOUNDATION_GATE.md` と `docs/PROGRESS.md` に記載しています。

AmuOSのv0.6.0プレリリースです。この版では、Linux・Windowsのホストに置いたファイルを、ホスト詳細画面から扱えるようになりました。Agentで公開したディレクトリに範囲を絞り、一覧の確認、転送、テキスト編集、名前変更や移動などができます。まだ開発途中ですが、試していただいて気づいたことがあれば、Issueで教えていただけるととても助かります。

> [!WARNING]
> 開発途中のソフトウェアです。今回の確認はCIを中心としたもので、すべての環境や長期間の運用を保証するものではありません。APIやデータ形式も予告なく変わることがあります。本番環境やインターネットに公開された環境での利用はお控えください。

## 新しくできること

- **ホスト詳細からのファイル管理**：ファイル・ディレクトリの一覧と情報、アップロード・ダウンロード、ファイル・ディレクトリ作成、UTF-8テキスト編集、名前変更・移動・削除に対応しました。1ファイルは256 KiBまで、一覧は1,000件まで、1ホストのルート設定は16個までです。ディレクトリの削除は空の場合に限ります。
- **操作できるディレクトリと権限の設定**：Agent側のローカル設定と、管理画面のホスト別ルート設定の両方で許可します。閲覧・変更を許すロールをディレクトリごとに選び、ホストの範囲と同じ割当で照合します。Viewerには変更を許可できません。OSのアクセス権とAgent側の読取り専用設定も適用します。既定のAgentはファイル管理を無効にしたままです。
- **競合と変更前データの扱い**：上書き・移動・削除には、取得時のETagと確認が必要です。書込みは一時ファイルを同期してから公開し、編集・削除前の通常ファイルをホスト側の非公開領域へ退避します。退避データの復旧と容量管理は、Agentを停止したうえでホスト管理者が行います。
- **ファイル操作のタスクと監査**：操作の受付・配送・結果を、既存の永続タスクと監査で確認できます。同じ要求や結果の再送で二重実行せず、再起動などで結果が分からない操作はunknownとして保留します。ファイルタスクは汎用の「再実行」では繰り返さず、ホストの状態を確認してから新しい要求で扱います。ファイル内容は監査に記録しません。
- **Windows短縮パスの修正**：CIで見つかった、`RUNNER~1`などの8.3短縮名をリンクと誤判定する不具合を修正しました。短縮名と実NTFSジャンクションの回帰試験を追加し、リンク・reparse pointの拒否を維持しています。
- READMEのファイル管理・ホスト詳細・監視・ホスト一覧・概要の画面例を、最新のUIとサンプルデータで更新しました。

## はじめかた

Windowsでは `amuos_0.6.0_windows_amd64.zip`、Linuxでは `amuos_0.6.0_linux_amd64.tar.gz` と `SHA256SUMS` をダウンロードし、ハッシュを照合してから展開してください。

Windowsは同梱の `INSTALL-WINDOWS.md`、Linuxは `INSTALL.md` に、Control Planeの導入、初回設定、Agentの登録、更新と切り戻しの手順があります。Windowsサービスの登録には、管理者として起動した64ビットPowerShellが必要です。

ファイル管理を使う場合は、同梱の `FILES.md` に従い、Agentの実行ユーザーと信頼する管理者だけが書き込める専用ディレクトリを用意します。Agentの `--file-roots` でルート名・絶対パス・読取り専用の有無を設定し、ホスト詳細画面でも同じルート名と許可ロールを登録してください。Windowsの新規サービス導入では `-FileRoots` を指定できます。Linuxのsystemdでは、同じ資料にある実行引数と書込み許可範囲のoverrideを追加します。

## v0.5.0 からの更新

データベースをスキーマv13からv14へ自動移行し、既存のタスクと試行を保持します。Linux・Windowsとも、同梱の導入手順の「更新」に従い、停止・更新前バックアップ・本体の差し替え・再起動を行ってください。Control PlaneとAgentの両方を、この版へ更新してください。ファイル管理の設定を追加しなければ、従来の監視機能のまま利用できます。ソースからのビルドにはGo 1.27.3以降が必要です。

移行後のデータベースに、v0.5.0の本体だけを戻す方法には対応していません。切り戻しに備え、旧本体と更新前のバックアップを組で保管してください。バックアップからの復元は、従来どおり作成時と同じ版の本体で行います。v0.5.0のバックアップをv0.6.0へ直接復元する方法には対応していません。

Control Planeをバックアップから復元した場合は、ログイン中のセッションとAgentの資格情報が無効になります。各Agentを新しいコードで登録し直してください。受付待ちを含むファイル操作もunknownとして保留し、自動では配送・再実行しません。

ファイルのルート権限設定とタスクの転送内容は、保護された管理基盤DBに保存され、基盤バックアップにも含まれます。Agentのタスクジャーナルにも転送内容が残ります。一方、ホスト側の実際のファイル一式・退避領域・ローカルルート設定は、基盤バックアップには含まれません。それらは別に保護してください。詳しくは `BACKUP.md` と `FILES.md` をご覧ください。

## まだできないこと

- 256 KiBを超えるファイルの転送・編集、空でないディレクトリの削除、既存の移動先への上書き、Web画面からの退避データ復旧
- 信頼しないOSユーザーとの共有ディレクトリ、他プロセスによる同時変更、マウントの付替えを伴うファイル操作。Windowsの許可ディレクトリはローカルNTFSに限ります
- アプリのデプロイと実行環境の設定、Docker/Compose、VM管理。これらは今後の版で取り組む予定です
- 管理画面からのWindowsサービスやsystemdサービスの開始・停止。systemdの状態取得はLinuxのみです
- WindowsでのLoad・Swap・起動時刻、64論理CPUを超えるホストのCPU使用率の取得。ディスクI/Oも監視カウンターが利用できる環境に限られます
- 自動バックアップのスケジュール、Webからの復元、異なる版へのバックアップの直接復元

## 確認した環境

- GitHub ActionsのLinux・Windowsで、Goのテストと静的検査、認可・監視データの保持・復元、依存関係の脆弱性検査を実行しました。Linuxではrace検査と、ファイル書込み・バックアップ・復元時の実際の容量不足も確認しました。
- 両OSで、実Agentを使ったファイル転送・編集・移動・ダウンロード・削除、Control PlaneとAgentの再起動を含むブラウザーE2E全6件が成功しています。上限256 KiBのmTLS転送、古いETagの拒否、権限剥奪、再送、ジャーナル再開、監査への本文非漏えい、v13からの移行と移行失敗時のロールバックも確認しました。
- LinuxではOSの書込み権限とリンク差替え、Windowsでは8.3短縮名と実NTFSジャンクションを確認しました。symlink作成の権限がない環境では、その作成を伴う試験をskipします。ジャンクション試験は別に実行しています。
- Ubuntu 24.04・Debian 13での配布物の導入、Ubuntuのsystemdによる常駐・更新・切り戻し、Ubuntuで作ったバックアップの空のDebian環境への復元を確認しました。Windowsでも、配布物によるサービス導入・NTFS保護・更新・切り戻しを確認しました。
- 実機での長時間運用や、電源断を伴う確認は実施していません。403,200件の保持量試験は時刻を指定して生成したデータによるもので、実時間で7日間運転した結果ではありません。試験条件と範囲は `docs/FOUNDATION_GATE.md`、`docs/TESTING.md`、`docs/PROGRESS.md` に記載しています。

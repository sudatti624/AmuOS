AmuOSの3つ目のプレリリースです。この版から、管理対象のLinuxホストに置くAgentが加わりました。Agentを一回限りのコードで登録すると、ホストの情報や監視値（CPU・メモリ・ディスク・ネットワークなど）とその履歴、systemdのサービスの状態を画面で確認できます。画面から収集を依頼し、結果を確かめることもできます。まだ開発途中ですが、試していただいて気づいたことがあれば、Issueで教えていただけるととても助かります。

> [!WARNING]
> 開発途中のソフトウェアです。実機での長時間の運用や、独立した環境での復元の確認はまだ済んでいません。APIやデータ形式も予告なく変わることがあります。本番環境やインターネットに公開された環境での利用はお控えください。

## 新しくできること

- **Agentの登録と接続**：ホスト画面で発行する一回限りのコード（有効10分）で登録します。登録後のAgentは、mTLS専用のポート（既定9443）だけを使います。Agent用の証明書は、Control Planeが自動で作る専用の認証局で発行します。資格情報は30日有効で、期限が近づくとAgentが自動で更新します。ホストを失効・削除すると、そのAgentはすぐに拒否されます。
- **ホスト情報と監視値**：Agentは `/proc` などから15秒ごとに値を集めます。特別な権限は必要ありません。ホストの詳細画面では、現在の値、ホスト情報、ディスクとネットワークインターフェース、1時間〜30日の履歴グラフを表示します。取得できなかった値は0とせず「取得できません」と表示し、データのない区間はグラフの線を切ります。
- **通信が切れたとき**：送れなかった値は、Agentが最大10分・10MiBまで手元に持ち、つながり直したら送ります。同じ値が二度送られても、二重には保存しません。
- **保存と集約**：生データは7日、5分単位の集約（件数・最小・最大・平均）は30日保持します。保持期間と収集間隔は、設定画面で変更できます（全体のオーナー・管理者のみ）。
- **systemdのサービスの状態**：サービスの読み込み・稼働状態を、読み取りだけで表示します。開始・停止などの操作は提供していません。
- **収集タスク**：ホストの詳細画面の「今すぐ収集」で、ホスト情報・監視値・サービスの状態をその場で取り直せます。通信が切れても同じ作業を二度実行しないよう、作業の記録をControl PlaneとAgentの両方に残します。結果が確かめられなかった作業は「結果不明」として残し、確認した根拠を付けて確定できます。終わった作業は、元の作業への参照を持つ新しい作業として再実行できます（1つの系列で3回まで）。
- **復元とAgent**：Control Planeをバックアップから復元すると、すべてのAgentの資格情報を無効にし、Agent用の認証局も作り直します。各Agentは、新しいコードで登録し直します。

## v0.2.0 からの更新

同梱の `INSTALL.md` の「更新」の手順で、更新前にバックアップを取ってから差し替えてください。データベースは起動時に新しい形式（スキーマv13）へ自動で移行されます。移行したあとに古い本体へ戻すときは、更新前のバックアップと、そのとき残しておいた本体の組を使ってください。

この版では、Agent用のポートの設定（`AMUOS_AGENT_ADDR`、既定 `127.0.0.1:9443`）が加わりました。v0.2.0 から更新する場合は、次の2つを行ってから、`systemctl daemon-reload` と再起動を行ってください。

- `/etc/amuos/controlplane.env` に `AMUOS_AGENT_ADDR=127.0.0.1:9443` の1行を追加します。ほかの行は変えないでください（ファイルごと入れ替えると、ご自身で設定したアドレスやURLが消えてしまいます）。
- `/etc/systemd/system/amuos-controlplane.service` を、この版の `packaging/amuos-controlplane.service` に入れ替えます。

`AMUOS_AGENT_ADDR` を追加せずにユニットファイルだけを入れ替えると、正しく起動しません。順番にご注意ください。Agentを別のホストで動かす場合の設定は、`INSTALL.md` の「Agentの導入」をご覧ください。

## まだできないこと

- Windows への対応（Control PlaneとAgent。次の版で取り組む予定です）
- ワークロード別の監視、外部の監視サービスとの連携
- 自動バックアップのスケジュール、Webからの復元
- Linux amd64 以外向けの配布
- 実機での長時間の運用と、独立した環境での復元の確認

## 確認した環境

- GitHub Actions の Ubuntu 24.04 で、この配布ファイルのControl PlaneとAgentをsystemdのサービスとして導入しました。そのうえで、Agentの登録・接続、ハードニングした設定での監視値・サービスの状態の取得、収集タスクの実行、Agentを止めてもControl Planeに影響しないことを確認しました。v0.2.0 までの更新・切り戻し・アンインストールの確認も続けています。
- Ubuntu 24.04 と Debian 13 のコンテナで、手順どおりの手動導入、Agentの登録と監視値の到達、暗号化バックアップと復元、復元後に古いAgentの資格情報が拒否されることを確認しました。
- Ubuntu 24.04 で取ったバックアップを、AmuOSを動かしたことのない Debian 13 のコンテナへ復元できることを確認しました。
- 実機の Ubuntu Server や Debian での長時間の運用、時計の大きなずれや電源断を伴う確認は、まだ行っていません。

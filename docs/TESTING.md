# 検証計画

仕様v0.4 §16に対応。Go単体・SQLite統合・httptestを使用する。期待値を満たさない項目は完了扱いしない。

| 要件 | 試験と期待値 |
|---|---|
| §10 認証 | 初回設定・ログイン・Cookie・ログアウト成功。期限境界、トークン再利用、無効ユーザー、誤パスワードを拒否 |
| §10 RBAC | Admin(A)+Viewer(B)でB管理不可、グループ離脱が既存セッションに即時反映、無効ユーザーを拒否 |
| §10 Owner | 範囲付き/グループOwnerを拒否、Admin/Operator/ViewerのOwner専用操作を拒否。状態変更の再認証、5分境界・セッション分離、並行無効化でも有効Ownerが残ることを検証。ロール移譲は未実装 |
| §10 招待 | 固定名・範囲、トークンハッシュ保存、期限・取消・再発行・一回限り/同時受諾、発行者の無効化・権限変更、対象ホスト削除を検証 |
| §10 アカウント | パスワード変更・無効化で全セッション削除、再有効化しても旧セッション/招待が復活しないこと、監査保存失敗のロールバックを検証 |
| §14 移行 | v1ユーザー・セッションをv2へ移行し、新しい再認証権限を付与しないこと、途中失敗時に列追加・版更新が残らないことを検証 |
| §12 CSRF | Origin不一致・CSRF欠落を拒否、Cookieの安全属性、不明JSON字段を拒否 |
| §12 監査 | 成功・認証失敗・一部認可拒否を保存。監査トリガーで書込み失敗を注入し、ホスト追加がロールバックされる |
| §4 ホスト | 権限のあるpendingホストのみ一覧表示、範囲外監査・全体イベントを漏らさない |
| §14 永続性 | 一度DBを閉じて再接続し、セッション・ホスト・監査が残る。これはバックアップ復元試験とは別 |
| §1.4 範囲 | Docker・デプロイ・ファイル・VM・サービス変更のルートが存在しない |

実行: `go test ./...`、`go vet ./...`、Linuxでは `go test -race ./...`。結果はPROGRESS.md。Go形式チェックは `gofmt -l cmd internal` が空であること。

HTTP統合試験でも招待の追加フィールドによる範囲変更拒否、受諾・取消、ユーザー無効化・再有効化、パスワード変更時のCookie削除と失効、Owner再認証と最後のOwner保護を確認する。

グループ管理では直接割当と所属経由の範囲分離、既存セッションへの権限変更の反映、Owner所属の変更制限、重複・欠落・入れ子の拒否、削除と監査失敗時のロールバック、再起動後の所属/割当保持を確認する。権限の剥奪後に再付与しても古い招待・再認証が復活しないことも検証する。

未実施: Playwright主要画面E2E、Owner移譲APIの検証、mTLS実Agent・同時登録・失効・更新、全タスク障害注入、暗号化バックアップの破損/誤鍵/独立復元、両Linuxのクリーン導入、24時間負荷、依存脆弱性とリリースレビュー。これらを単体テストで代替したと扱わない。

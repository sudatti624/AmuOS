# 検証計画

仕様v0.4 §16に対応。Go単体・SQLite統合・httptestを使用する。期待値を満たさない項目は完了扱いしない。

| 要件 | 試験と期待値 |
|---|---|
| §10 認証 | 初回設定・ログイン・Cookie・ログアウト成功。期限境界、トークン再利用、無効ユーザー、誤パスワードを拒否 |
| §10 RBAC | Admin(A)+Viewer(B)でB管理不可、グループ離脱が既存セッションに即時反映、無効ユーザーを拒否 |
| §10 Owner | 範囲付き/グループOwnerを拒否、Admin/Operator/ViewerのOwner専用操作を拒否。状態変更・追加・解除・移譲の再認証、5分境界・セッション分離、並行無効化/解除でも有効Ownerが残ることを検証 |
| §10 招待 | 固定名・範囲、トークンハッシュ保存、期限・取消・再発行・一回限り/同時受諾、発行者の無効化・権限変更、対象ホスト削除を検証 |
| §10 アカウント | パスワード変更・無効化で全セッション削除、再有効化しても旧セッション/招待が復活しないこと、監査保存失敗のロールバックを検証 |
| §14 移行 | v1ユーザー・セッションをv2へ移行し、新しい再認証権限を付与しないこと、途中失敗時に列追加・版更新が残らないことを検証 |
| §12 CSRF | Origin不一致・CSRF欠落を拒否、Cookieの安全属性、不明JSON字段を拒否 |
| §12 監査 | 成功・認証失敗・一部認可拒否を保存。監査トリガーで書込み失敗を注入し、ホスト追加がロールバックされる |
| §4 ホスト | 権限のあるpendingホストのみ一覧表示、範囲外監査・全体イベントを漏らさない |
| §14 永続性 | 一度DBを閉じて再接続し、セッション・ホスト・監査が残る。これはバックアップ復元試験とは別 |
| §1.4 範囲 | Docker・デプロイ・ファイル・VM・サービス変更のルートが存在しない |
| §11・§16.1 画面 | Playwrightで実バイナリを起動し、初回設定・再設定の拒否・ログイン失敗/成功・再読込・ログアウト（サーバーセッション失効）、招待の発行と受諾、Viewerの表示制限と画面で隠したAPIの直接呼出し拒否（403）、グループでのAdmin付与・剥奪が既存セッションに即時反映、ホスト登録枠、監査閲覧、Ownerの再認証による保持設定変更、パスワード変更による全セッション失効を確認。CSP違反とページ内エラーがないこと |
| §12 画面配信 | 画面のHTMLは応答ごとに異なるnonceとCSPを返し、プレースホルダーを残さない。`/assets/` の不正パス・隠しファイル・未登録拡張子は監査付き404。APIのCSPは変更しない |

実行: `go test ./...`、`go vet ./...`、Linuxでは `go test -race ./...`。`web/` では `pnpm exec vp check`・`pnpm exec vp test`、ビルド済みの `dist/controlplane` と `dist/devcert` を使って `pnpm exec playwright test`。結果はPROGRESS.md。Go形式チェックは `gofmt -l cmd internal` が空であること。

HTTP統合試験でも招待の追加フィールドによる範囲変更拒否、受諾・取消、ユーザー無効化・再有効化、パスワード変更時のCookie削除と失効、Owner再認証と最後のOwner保護を確認する。

グループ管理では直接割当と所属経由の範囲分離、既存セッションへの権限変更の反映、Owner所属の変更制限、重複・欠落・入れ子の拒否、削除と監査失敗時のロールバック、再起動後の所属/割当保持を確認する。権限の剥奪後に再付与しても古い招待・再認証が復活しないことも検証する。

Owner移譲では両者の全セッション失効、移譲元の全体Admin化、移譲先のOwner化、無効ユーザー・自己への移譲拒否、監査失敗時の原子性、再起動後の保持を検証する。Owner無効化の並行試験でも、テスト内の直接DB更新ではなく実際のOwner追加APIを使って準備する。

HTTP監査ではサーバー発行のrequest_idと業務・拒否イベントの相関、同時発行の一意性、偽造ヘッダー・本文・URL・クエリ・Cookieの秘密値除外、セッション非延長、切断後の記録、保存失敗の503、正常な生存確認の継続、再起動後のID保持を検証する。

監査保持では既定180日と1〜3650日の設定制約、Owner専用の再認証、期限境界の保持、1000件の上限、同時バッチの非重複、前後設定と削除範囲のdetails、監査保存失敗時の設定/削除ロールバック、再起動後保持を検証する。HTTPのnull本文・個別ID指定・CSRF欠落も拒否する。

順序0/1の完了確認はFOUNDATION_REVIEW.mdに対応付ける。API_AUTHORIZATION.csvとchiの全ルート（API 27・画面配信10）を照合し、公開可能な4経路と画面配信の固定パスを固定する。全sessionルートの未認証拒否と変更要求のCSRF欠落拒否、業務状態の非変更を検証する。自動保持の予定/再試行/停止、ホスト作成の同時6要求・再起動再取得・入力競合・再認可・期限切れ拒否も含む。

WindowsのCLIスモークはビルド後に `scripts/check-startup.ps1` を実行する。TLS欠落/不正で状態を作らないこと、ローカル初回設定、既存トークンを上書きしないことを確認し、生成した状態は検証済みの作業用.cache配下から削除する。トークンを標準出力に出さない。

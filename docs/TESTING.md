実行: `go test ./...`、`go vet ./...`、Linuxでは `go test -race ./...`。`web/` では `pnpm exec vp check`・`pnpm exec vp test`、ビルド済みの `dist/controlplane` と `dist/devcert` を使って `pnpm exec playwright test`。結果はPROGRESS.md。Go形式チェックは `gofmt -l cmd internal` が空であること。

HTTP統合試験でも招待の追加フィールドによる範囲変更拒否、受諾・取消、ユーザー無効化・再有効化、パスワード変更時のCookie削除と失効、Owner再認証と最後のOwner保護を確認する。

グループ管理では直接割当と所属経由の範囲分離、既存セッションへの権限変更の反映、Owner所属の変更制限、重複・欠落・入れ子の拒否、削除と監査失敗時のロールバック、再起動後の所属/割当保持を確認する。権限の剥奪後に再付与しても古い招待・再認証が復活しないことも検証する。

Owner移譲では両者の全セッション失効、移譲元の全体Admin化、移譲先のOwner化、無効ユーザー・自己への移譲拒否、監査失敗時の原子性、再起動後の保持を検証する。Owner無効化の並行試験でも、テスト内の直接DB更新ではなく実際のOwner追加APIを使って準備する。

HTTP監査ではサーバー発行のrequest_idと業務・拒否イベントの相関、同時発行の一意性、偽造ヘッダー・本文・URL・クエリ・Cookieの秘密値除外、セッション非延長、切断後の記録、保存失敗の503、正常な生存確認の継続、再起動後のID保持を検証する。

監査保持では既定180日と1〜3650日の設定制約、Owner専用の再認証、期限境界の保持、1000件の上限、同時バッチの非重複、前後設定と削除範囲のdetails、監査保存失敗時の設定/削除ロールバック、再起動後保持を検証する。HTTPのnull本文・個別ID指定・CSRF欠落も拒否する。

順序0/1の完了確認はFOUNDATION_REVIEW.mdに対応付ける。API_AUTHORIZATION.csvとchiの全ルート（API 45・Agent 7・画面配信11）を照合し、公開可能な4経路と画面配信の固定パスを固定する。全sessionルートの未認証拒否と変更要求のCSRF欠落拒否、業務状態の非変更を検証する。自動保持の予定/再試行/停止、ホスト作成の同時6要求・再起動再取得・入力競合・再認可・期限切れ拒否も含む。

WindowsのCLIスモークはビルド後に `scripts/check-startup.ps1` を実行する。TLS欠落/不正で状態を作らないこと、ローカル初回設定、既存トークンを上書きしないことを確認し、生成した状態は検証済みの作業用.cache配下から削除する。トークンを標準出力に出さない。

状態ディレクトリの排他は `internal/statelock` で検証する。同じディレクトリの別DB名・別プロセスの取得を拒否し、別ディレクトリは独立して使用できること、正常解放・子プロセスの強制終了後に残ったロックファイルで再取得できること、非ファイルのロックと非ファイルDB指定を拒否することを確認する。`cmd/controlplane` ではロック中の初回設定がDB・資格情報を作らないこと、解放後に発行できること、発行失敗でもロックを解放すること、不正TLSで状態ディレクトリを作らないことを検証する。Linuxでの実行はCIのgo/raceジョブで行う。

タスク配送はmTLSでの正常collect、同一配送・結果再送、異なる結果・別ホスト・失効・期限切れの拒否、監査失敗のロールバック、Agent再生成と未完了ジャーナルのunknown回復を試験する。systemdのユニットハードニングはsmoke-systemd.shでネットワーク値・サービス状態・タスクの到達とAgent停止後のControl Plane生存を確認する。

CIを主な出荷判定にし、Ubuntu Server 24.04/Debian 13/Windowsの宣言した対応範囲で、実バイナリ/配布物・サービス・権限・操作・障害/復旧を検証する。クリーン環境復元は引き続き必須だが、コンテナ/VM/別状態ディレクトリ等でCIから再現してよい。専用環境を要する機能はセルフホスト型CIも利用し、未実施を成功扱いしない。24時間運転や別途の実機手動試験は一律必須にせず、必要に応じた補助検証とする。

反復/負荷試験は操作回数・負荷・データ量・実行時間・合格基準を事前に定める。保持/集約/資格情報/時計の境界は時計注入や事前データでも検証し、実時間での長時間運転を実施したとは記録しない。試験ごとに候補版・環境・期待値/実測値・証跡・未実施を残し、管理基盤とワークロードデータ/ボリューム/VMディスクの復元対象を区別する。

環境固有の問題はIssueの環境情報と手順から再現し、修正時に可能な限りCI回帰試験へ追加する。既知の認可不備・データ破損・復元不能などを利用者の発見に委ねない。上の過去記録にある24時間/実機必須という方針は、本節とADR-026に置き換える。

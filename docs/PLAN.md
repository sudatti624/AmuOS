## リリースの目安

ソフトウェアの版は上の順序に対応させる。各版は、該当する順序の項目が完了条件を満たし、CIが成功し、できること・できないことを明記したリリースノートを用意してから出す。1.0より前は互換性を保証せず、本番利用を推奨しない。仕様書の版（SPECIFICATION.md v0.4）とソフトウェアの版は別の番号である。

| 版 | 目安 |
|---|---|
| v0.1 | 順序1〜3。画面からログイン・ユーザー/グループ/権限の管理ができ、Ubuntu ServerまたはDebianに手順どおり導入して試せる（Ubuntu 24.04・Debian 13への導入をCIで確認、ADR-014） |
| v0.2 | 順序4。systemdでの常駐、整合性のあるバックアップ・復元、再インストールなしの手動更新ができる（運用の基盤を先に届け、Agent導入による大きなスキーマ変更の前に更新前バックアップを取れるようにするため、順序5より先に出す） |
| v0.3 | 順序5。Agentを登録し、ホストの情報・監視値・履歴を画面で確認できる |
| v1.0 | 順序6。仕様§16の初期リリース条件（独立環境での復元、認可総合検証、24時間連続運転など）をすべて満たす |

v1.0より後の候補（MCP対応など）は仕様§17に置き、v1.0の条件を満たすまで着手しない。

それ以前に区切りを付ける場合は `v0.1.0-alpha.N` などのプレリリースとし、対象範囲（例: APIのみ）を明記する。24時間連続運転は、予行演習をWSLなどで行ってよいが、v1.0の証跡はUbuntu Server・Debianの独立したVMで取得し、実施環境を記録する。

# v0.5 基盤検証

2026-11-09：4a8cfc0の[CI run 42635099511](https://github.com/sudatti624/AmuOS/actions/runs/42635099511)で全9必須ジョブが成功し、基盤ゲートを通過した。v0.5.0のタグ・リリースは未作成。

仕様v0.5 §14.6・§16.1、ADR-026に対応する。基盤ゲートの通過には、この資料の追加試験と既存CIの全必須ジョブの成功が必要。試験の追加だけでは通過としない。

## 条件と合格基準

| 試験 | 固定条件 | 合格基準 |
|---|---|---|
| HTTP認可 | Host AのAdmin/Operator/ViewerとHost BのViewerを組み合わせる | 詳細・履歴・systemd状態・タスクの読取り成功、Bの登録コード発行拒否、ホストAdminの全体管理拒否。権限剥奪後の同じセッションはAを一覧から除外し個別取得404。無効化と再有効化で旧セッションが復活しない |
| 同時操作・配送 | 10ホスト、同時5ユーザー、各ホスト15秒刻み240サンプル、ユーザーごと20タスク | サンプル2,400件、タスク100件、試行100件。送信・作成・結果の再送でも増えない。各ユーザーの他ホスト参照を拒否。処理エラーや欠測なし |
| 保持量 | 10ホスト×7日×15秒間隔=403,200件。CPU・メモリを入力、他項目は欠測 | 1日単位の集約を反復し、生保持期限後の345,600件と集約40,320行を確認。CPUの集約count合計403,200。再処理でDBページが増えず、全期限経過後に生/集約を削除してページを再利用可能にする |
| 独立復元 | 同時操作試験のDBを停止して暗号化バックアップ。別の空ディレクトリへ復元 | 10ホストの履歴が一致。ユーザー・権限・タスク・試行件数が一致。5ユーザーのホスト範囲を維持。全旧セッション・Agent資格情報拒否。新CAで再登録してサンプル受付を再開 |
| 容量不足 | Linuxの専用32MiB tmpfsをENOSPCまで埋める | バックアップの未完成ファイルを公開しない。復元失敗で既存DBを変更しない。空きを戻すと整合性検査と再復元が成功 |
| 画面・再接続 | 実Agent停止、60秒の接続期限、Control Plane再起動、同じAgentの再起動 | 切断表示→接続中への復帰。セッションとホスト登録を維持。失効・削除、監査と登録秘密値の非漏えいを確認 |

同時操作試験はStore APIの統合試験で、HTTP/mTLS通信は既存のAgent試験とE2Eで確認する。データ量試験の時計は注入・事前生成であり、実時間で7日/24時間運転した結果ではない。復元性能試験の対象は2,400サンプル・100タスクであり、403,200件の暗号化バックアップ性能を実測したとは扱わない。メモリは試験前後のGoヒープ、容量はDBページ数と復元DBサイズを記録する。OS全体の最大メモリを測定する試験ではない。

各Go追加試験は5分の処理期限、CI呼出しは10分の上限を設ける。バックアップ15分以内・復元から収集再開60分以内という設計目標を超えたら失敗する。実測値はCIの`foundation-<OS>` artifactに保存する。

403,200件の保持量試験は通常Go試験と両OSのfoundationジョブで必須とする。SQLiteの生成Goコードにrace計測を付けた実行では5分の上限を超えたため、このデータ量試験だけをrace実行から除く。raceは`go test -race -skip '^TestFoundationRetentionVolume$' ./...`で行い、10ホスト/5ユーザーの並行処理・再送・配送、既存の保持/集約境界試験などは対象に残す。データ量と整合性の合格条件や通常実行の期限は変更しない。

## 実行

```sh
go test -v -count=1 -timeout=10m ./internal/controlplane ./internal/store ./internal/recovery -run '^TestFoundation'
# Linux専用。sudoとmountを利用できるCI環境で実行する。
bash scripts/check-foundation-capacity.sh
go run golang.org/x/vuln/cmd/govulncheck@v1.9.0 ./...
```

容量試験は通常のGo試験では専用環境なしとしてskipする。CIのfoundationジョブでは専用tmpfsを作り必ず実行し、失敗をreleaseジョブへ伝える。開発用のファイルシステムを埋めない。

既存の`go test ./...`・`go vet ./...`・Linux race・Web check/test/build・Playwrightを維持する。Ubuntu/Debian配布物導入、Ubuntu systemd更新/切戻し、Ubuntu由来バックアップの空Debian環境復元、Windowsサービス/ZIP試験も引き続き必須。未知の命令、不正CSR/証明書、認可失効、集約/時刻境界、監査失敗時ロールバック、通信断、ジャーナル再開、破損/誤鍵/形式不整合、中断したSQLite置換と保守プロセス強制終了は既存の単体・統合試験と組み合わせて確認する。

## レビュー範囲と残る判定

今回の変更は検証コード・CI・資料であり、新しい製品APIや高権限Agent命令を追加しない。HTTPの全ルート契約照合を維持し、未提供のファイル/デプロイ/コンテナ/VM/systemd変更も404で拒否する。新しい認証例外や秘密値のログ出力を加えない。容量試験の対象を小さいtmpfsに制限し、CIログには件数・サイズ・時間だけを残す。

リモートCI全ジョブの成功、依存検査の結果と既知の指摘の判断はPROGRESS.mdに記録する。未実施ジョブを成功として扱わず、このゲートが通るまでv0.6へ進まない。追加テストは全ての不具合や全環境での性能を保証するものではない。

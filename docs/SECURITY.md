# セキュリティ設計とレビュー

仕様v0.4 §2.5–2.6、§10、§12、§14を基準とする。

| 脅威 | 対策・検証 |
|---|---|
| パスワード/DB漏えい | Argon2id、秘密ファイル権限、トークンのハッシュ保存、秘密値のログ禁止 |
| セッション固定/CSRF | 新しい乱数、Secure/HttpOnly/SameSite、OriginとCSRF照合、絶対・アイドル期限 |
| 総当たり | IP単位の回数制限、ユーザー存在を明かさないエラー、認証失敗監査 |
| IDOR/権限合成の誤り | 同一割当内で操作・範囲照合、一覧も同じ認可、無効ユーザー優先 |
| 認可のTOCTOU | 最新割当とユーザーを同じDBトランザクションで再取得 |
| 監査欠落 | 重要更新とイベントの原子的コミット、監査書込み失敗なら更新中止 |
| 再起動/容量不足 | 永続DB、移行の原子性、エラー伝播、既存DBを削除して再作成しない |
| Agent偽装・削除後再接続 | mTLSと受入時DB照合、別CA、失効とデータ取込みの直列化（未実装） |
| バックアップ巻戻し | 全資格情報失効・CA再発行・タスクunknown保留（未実装） |
| 古い招待からの昇格 | 非Ownerの固定割当、発行/受諾時に最新の発行者権限を照合、無効化時に発行済み招待を取消 |
| アカウントの失効後復活 | パスワード変更・無効化で全セッションを削除、再有効化時も旧セッションを再利用しない |
| Owner不在/乗っ取り | 状態変更にセッションごとの明示的再認証、5分期限、最後の有効Ownerをトランザクションで保護 |
| Owner移譲の部分失敗 | 追加・解除・移譲を専用APIで認可し、権限・版・全セッション失効・監査を一つのトランザクションで確定 |
| グループ経由の昇格 | グループOwner禁止、所属追加で得る権限も部分集合を検証、Ownerを含むグループ変更は再認証付きOwnerに限定 |
| HTTP拒否の記録漏れ/秘密値混入 | サーバー生成リクエストID、固定ルート・理由コードのみ記録、切断後も上限2秒で保存を試行、失敗は503と秘密値を含まないログで通知 |
| 保持処理による証跡喪失 | 再認証済みOwnerのみ、期限と件数上限を固定し、削除と実施範囲の監査を原子的に保存 |

OS管理者に対する完全な監査改ざん防止は保証しない。TLS終端リバースプロキシ、分散レート制限、複数Control Planeは現在対象外。秘密値を含むクラッシュダンプの採取は避ける。

公開前に全APIの認可表、Owner専用操作、鍵の権限、依存脆弱性、エラー・監査の秘密値混入をレビューする。現在は開発段階であり、初期リリースの完了条件を満たしていない。
